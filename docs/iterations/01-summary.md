## 二、交付内容

### 沙盒运行时

- `sandbox/host.ts` —— 宿主侧：iframe 生命周期、握手、RPC、调用管理
- `sandbox/guest/frame.js` —— frame 引导：起 Worker，失败则降级并如实上报层级
- `sandbox/guest/runtime.js` —— guest 运行时：`definePlugin`、`host` 门面、清单校验、调用与取消
- 四层围栏：不透明来源 → frame CSP → 能力授权 → 文件收敛

### 能力层

- `capabilities/index.ts` —— 唯一的权限执行点，6 个命名空间共 18 个方法
- 每个入口都重新校验参数（参数来自不可信代码，不带任何类型保证）
- `net.fetch` 强制 `credentials: 'omit'`、限协议、限体积、默认阻断内网

### 存储

- `vfs/index.ts` —— OPFS 支撑的 VFS，功能探测降级到内存，元数据存 IndexedDB
- 流式写入（create → write* → close），刷新后可恢复

### 插件管理

- 两阶段安装：零权限沙盒试运行读清单 → 用户逐项授权 → 落盘
- `analyze.ts` 静态风险披露（明确定位为"披露"而非"控制"）
- `subscription.ts` 订阅同步，**能力集变化的更新一律扣下待审**
- `loader.ts` 依赖拉取 + SRI 校验 + IndexedDB 缓存

### UI

- 三栏布局、命令面板（子序列匹配）、任务队列浮窗、结果预览、ZIP 打包
- 完整的明暗主题 token、可视化主色/圆角调节、自定义 CSS 注入
- 手写 12 个 shadcn 风格原语，无组件库依赖

### 内置插件（即样板）

- **图片工具箱** —— 在沙盒内用 `OffscreenCanvas` 做真实像素计算，证明沙盒能干重活
- **PDF 工具箱** —— 声明 pdf-lib 依赖，证明依赖注入链路完整；含合并与页面提取两个工具

## 三、过程中发现并修复的问题

记录下来，因为它们都是架构本身暴露出来的，值得留痕：

1. **frame 引导源码的占位符未被替换。**
   `String.replace` 用字符串模式只替换首次出现，而首次出现在 frame.js 自己的文档注释里。
   结果是沙盒内联脚本带着字面量 `__RUNTIME_SOURCE__` 上线，抛 `Invalid or unexpected token`。
   已改为全局正则，并在注释中避免提及该 token。

2. **`postMessage` 无法克隆 Vue 响应式 Proxy。**
   `task.inputs` 是 `reactive` 数组的代理，结构化克隆直接失败。
   修复方式不是在调用方 `toRaw`，而是**在沙盒边界显式重建纯值**——
   边界本就不该信任调用方传来的对象形态。

3. **`host.image` 兜底路径会往工作区塞临时文件。**
   原实现把字节写成一个 `__staged` 文件再交给宿主解码，用户会看到莫名其妙的残留。
   实际上输入文件的 id 本就在手上，直接传即可。

4. **pnpm 11 的构建脚本审批机制变更。**
   `onlyBuiltDependencies` 已迁移为 `pnpm-workspace.yaml` 中的 `allowBuilds`。

## 五、下一轮建议

按优先级：

1. **接入 `@ffmpeg/ffmpeg`。** 跨源隔离已就位、`ffmpeg.*` 的协议与权限位已预留，
   剩下的是 WASM 加载、进度回传与 `-progress` 解析。这是工具矩阵里最大的一块空白。
2. **补单元测试。** `lib/zip.ts` 的 ZIP64 分支、`analyze.ts` 的模式匹配、
   `parseRanges` 的边界——这些用端到端测很别扭，用单测很自然。
3. **跨浏览器验证。** Firefox 与 WebKit 的包本机已有，重点看 blob Worker 是否降级、
   OPFS 是否退回内存模式。
4. **订阅链路的端到端测试。** 需要一个测试用 HTTP 端点。
5. **移动端导航。** <768px 时侧边栏隐藏，目前只能靠首页网格与命令面板。

### 需要你拍板的事项（下轮开工前）

- **FFmpeg 的 `run()` 形态**：是暴露原始 `args` 数组（灵活、但插件可以拼出任意命令），
  还是给一组声明式的高层操作（`transcode` / `trim` / `extractAudio`，更安全但覆盖面有限）？
  这会直接写进 Plugin API，事后更改属破坏性变更。
- **是否要把文件可见范围从"插件级"收紧到"调用级"**（见架构文档第 9 节）。
  这需要把调用 id 透传进 `host.fs.*`，同样是破坏性变更——**趁 v1 还没有第三方插件，
  现在改的成本最低**。

# 第 4 轮迭代总结

> 面向：项目负责人。回答「这一轮做了什么、为什么这样做、还剩什么」。

本轮的输入是上一轮验收时的要求：「还有你那些没做的，我们也完整做完」。
目标因此是把工具矩阵里所有「🔜 可行待做」清零；做不了或需要拍板的，写清楚卡在哪。

结果：矩阵中 **🔜 从 40 项降为 0**；已实现从 70 项增至 **121 项**（共 136 项，口径变化见矩阵「八」）；
剩下 5 项 ⚠️ 全部是需要负责人决定的取舍（见本文第五节），10 项 ❌ 是纯浏览器的硬边界。

## 一、本轮的关键判断

| 事项 | 做法 | 理由 |
| --- | --- | --- |
| PDF 涂黑 | 含涂黑区域的页面**整页栅格化**，并清空文档信息 | 只画黑框是假涂黑，底层文字仍可复制；宁可这些页面失去文字层 |
| PDF 放置类工具（盖章、签名、文字） | 在页面预览上拖框，坐标按页面旋转换算；换算用 pdf.js 的真实视口做单元测试 | 扫描件常带 `/Rotate`，按未旋转坐标放置会把签名贴到错误位置且横躺 |
| Whisper 的 KV 缓存 | 给 `onnx.run` 增加「保留张量」，缓存留在推理 Worker | 逐 token 在沙盒与 Worker 间复制 37 MB 缓存，拷贝会比推理还慢 |
| 物体擦除模型 | 默认 MI-GAN（MIT，28 MB，任意尺寸），可选 LaMa（208 MB） | 体积相差 7 倍，常见的去路人、去水印场景 MI-GAN 足够 |
| 人脸增强、上色 | **不接入**，列为需拍板 | 官方没有 ONNX 导出，只有匿名第三方转换，不应进入「来源 + SHA-256」信任链 |
| qpdf 的损坏修复 | 改用 pdf-lib 容错解析重建，qpdf 只做校验 | 该 wasm 构建关闭了异常捕获，qpdf 自己的恢复逻辑实测不工作 |
| 自动化流水线 | 做成平台功能「工作流」，不要求插件适配；交互型（`setup`）工具不能加入 | 每一步就是普通的 `run(ctx)`；交互参数无法由流水线提供，与其运行出无意义的结果不如直接不列出 |

Plugin API 的变化全部是新增（v2.2：`onnx` 保留张量与 `dispose`、界面事件 `ui.on('canvas')`），
**沙盒安全架构未改变**。qpdf 需要的 `fetch` 改写发生在依赖的打包产物内部，沙盒里的全局 `fetch` 依旧锁死（架构文档 12.3）。

### 2. 平台功能：工作流

- 侧边栏、顶栏与命令面板新增「工作流」入口；工具页头部可「以当前参数加入工作流」。
- 编辑步骤（添加、排序、逐步参数），拖入一次文件运行全部步骤，逐步显示输入 / 输出数量与跳过说明。
- 模板：图片发布（缩小 → 水印 → WebP）、扫描件增强 → OCR、扫描件 → 可搜索 PDF、PDF 替换颜色、PDF 逐页转 WebP。
- 导入 / 导出 JSON；中间文件在成功后自动清理。

### 3. 共享基础设施

- **中文字体资源**：Noto Sans SC 构建时按 SHA-256 下载，作为按需依赖资源供字幕烧录、水印、表情包、PDF 文字与可搜索 PDF 使用。
- **Whisper 词表**：从与模型同一提交的 `tokenizer.json` 生成，保证 token id 一致。
- **Emscripten 模块进沙盒**：qpdf 与 libarchive 的打包方式（架构文档 12.3）。

## 三、过程中定位并修复的问题

1. **图片水印在多线程 FFmpeg 上永久挂起**。定位到静态图片输入的帧级多线程解码与 `scale2ref` 互相等待，线程预算对静态图输入固定单线程（架构文档 12.1）。没有提供「关闭多线程」开关。
2. **签名板切换内容类型后变成空白**：画布节点重新挂载后转交的是新画布，插件还在画旧的。新增 `ui.on('canvas')` 事件。
3. **去红眼在正常照片上改动肤色**：第一版按红绿比例判断，在真实合影上 140 只眼睛里有 35 只被误改（眼周偏红的肤色与阴影）。
   改为「高亮且饱和的红色 + 只处理瞳孔中心的连通块 + 块大小合理」，剩余命中全部是样例图上真实存在的红点。
4. **降噪强度曲线过弱**：默认强度下平滑阈值与典型噪声同量级，只能去掉一半噪声。重新标定。
5. **内容感知缩放的描述夸大**：在人群照片上实测主体同样被挤压，说明改为如实描述适用场景。
6. **Whisper 未闭合的片段结束时间等于开始时间**（窗口 token 用尽时）；改为延续到窗口末尾。
7. **qpdf 在沙盒中无法加载**：它总是 `fetch` 自己的 wasm，而沙盒 `fetch` 是只读禁用桩。改为打包时改写（架构文档 12.3）。
8. **加密检测对需要密码的文件返回「未加密」**：同样源于该 qpdf 构建无异常捕获，结合输出文本判断。
9. **截断的 7z 提示「压缩包里没有文件」**：改为「空的或已损坏」。
10. 字体转换：fontkit 的命名空间导出、WOFF2 在同时保留 hinting 与 kerning 时输出 0 字节；Excel 文件因 MIME 含 `xml` 被当作文本预览。

## 四、验证方式里值得一提的

- 盖章坐标换算不是「看起来对」：单元测试用 pdf.js 的真实视口，逐个旋转角度验证四个角落点与内容朝向。
- 人脸检测、去红眼误判率、Whisper 转写、MI-GAN / LaMa 的掩码约定，都先在 Node 里用真实模型与真实照片验证，再写进插件。
- 端到端测试在真实 Chromium 中下载、校验并运行全部模型（MI-GAN、YuNet、Whisper base 等）。

## 五、没有做的与原因

| 项目 | 状态 | 需要的决定 |
| --- | --- | --- |
| 数字证书签名、验签 | ⚠️ 需拍板 | 证书与私钥的存储与授权方式属于沙盒安全设计：沿用 `secret` 保险库，还是每次临时导入；插件能否接触私钥本体。**按协作约定暂停，等待确认** |
| PDF 时间戳 | ⚠️ 需拍板 | 必须联网访问 TSA，是否作为默认关闭、显式授权 `net` 的可选插件 |
| AI 人脸增强 / 老照片修复、黑白上色 | ⚠️ 需拍板 | 是否由项目从官方权重自行导出 ONNX 并公开托管；CodeFormer 为非商用许可，只能考虑 GFPGAN / DDColor |
| PDF/A、EPS | ❌ | Ghostscript（AGPL）；如需要，应作为独立可选插件 |
| 从扫描件自动识别表单字段 | ❌ | 需要版面分析模型，无合适的开源许可模型 |
| AI 扩图、HTML 转图片、Office 互转、PDF 文字编辑、EPUB/MOBI 互转 | ❌ | 纯浏览器边界，见工具矩阵 |
| 加密了文件名的 RAR | 不支持 | libarchive 本身不支持，工具会明确提示改用 7-Zip / WinRAR |

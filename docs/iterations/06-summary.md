# 第 6 轮迭代总结

> 面向：项目负责人。回答「这一轮做了什么、为什么这样做、还剩什么」。

本轮的输入：

1. 按主流开源项目的标准补齐 Markdown 文档、CHANGELOG 与开源协议（选定 MIT）。
2. 推送到 GitHub。
3. 在仓库中做一批与大模型相关的扩展，例如 AI 翻译、利用归一化坐标的 VLM 目标检测打标，越多越好。它们需要联网或本机 Ollama，因此不随程序本体分发、不内置，由维护者通过 jsDelivr 提供订阅；接口兼容 OpenAI，API Key 使用 `secret` 能力保管。
4. 工作流页面默认显示已创建的工作流，点「新建」后才显示模板并输入名称；流程图节点应能上下移动而不是固定位置；进入编辑后不共享应用布局（与教程一致）；工作流卡片上加图钉，置顶后像普通工具一样直接上传或输入并运行，把工作流「固化」。
5. 订阅安装审查对话框的内容超出了对话框，需要修复。
6. 测试「PDF 高清重置 → OCR」工作流时，输出 PDF 里的中文全部变成方框乱码：是预览的问题还是转换的问题？
7. 音视频转频谱图很慢，是否可以引入快速 FFT 之类的库。
8. 重复导入同一素材会让工作区空间变大；选素材时希望能从素材库中选择，并按工具过滤好。
9. 增加偏程序员的工具：二进制、时间戳获取与转换、Base64、JWT 等，包括但不限于。

### 开发者工具箱

新增内置插件「开发者工具箱」与分类「开发者工具」，共 16 个工具：时间戳转换、进制转换、Base64 编解码、JWT 解析与签名、哈希与校验和、URL 解析与编解码、UUID / ID 与密码生成、正则表达式测试、文本对比、Cron 表达式解析、十六进制查看、命名风格转换、字符串转义、JSON 转类型定义、Unix 权限计算、颜色格式转换。多数是实时面板，结果区带「复制」按钮；也都可以「导出为文件」。

为此对 Plugin API 做了两处向后兼容的新增：分类 `dev`，以及带复制按钮的 `code` 面板节点（插件无法访问剪贴板）。数据工具箱里原有的「编码与哈希」保留不动，开发者工具箱中的 Base64 与哈希功能更完整（URL 安全字母表、Data URI、二进制识别、MD5 / CRC32 / HMAC、期望值比对）。

## 二、关键决策

1. **一个插件而不是一组插件**。连接设置（`kv`）与 Key（`secret`）都按插件 id 隔离，拆开后每个工具都要重新配置、重新录入 Key。
2. **Key 绑定接口的 origin**。插件只在请求头里写 `{{secret:apiKey}}`，由宿主替换，且仅限录入时指定的域名。更换服务商后工具会主动请求重新录入，而不是让请求在宿主处失败。
3. **服务商差异在插件里消化，不要求用户理解**。不支持 JSON 模式时自动去掉 `response_format` 重试；429 / 5xx 按 `Retry-After` 退避；剥离推理模型的 `<think>`；从代码块或说明文字中提取 JSON。
4. **翻译保证格式不被模型破坏**。Markdown 的代码块不发给模型；字幕按条以 JSON 数组往返，条数对不上就逐条重译，避免时间轴错位；i18n JSON 只提取字符串值，键和结构不经过模型。
5. **目标检测只用一种内部表示**。提示词要求 0–1000 归一化坐标；解析端识别 Gemini 的 `box_2d`、0–1 小数与 Qwen2.5-VL 的绝对像素（相对于发送的缩放图），统一落到 0–1 后再导出 YOLO（归一化）与 COCO / LabelMe（原图像素）。
6. **本机模型不开后门**。Ollama / LM Studio 仍受「插件访问本机与内网」开关约束；README 写清了开关与模型服务端的跨域设置，错误信息也会提示。

## 三、过程中发现并修复的问题

1. **通过导入或订阅安装的插件，刷新后消失**（既有缺陷，影响所有非内置插件）。审查对话框把候选插件放在 `ref` 中，`commitInstall` 拿到的是响应式代理，IndexedDB 无法克隆；`persist()` 吞掉了异常。现在先 `toRaw`，写入纯 JSON 快照，失败时提示。内置插件每次启动重新登记，所以之前的测试一直没有覆盖到。
2. **批量请求使用凭据时提示刷屏**。每个请求一条提示，一次翻译就是几十条。改为同一插件、同一域名、同一组凭据在 15 秒内合并为一条，并显示次数。每次使用仍被提示与记账。
3. **安装审查误报「直接网络调用（将被拦截）」**：规则把 `host.net.fetch(` 也当成了裸 `fetch(`，所有正确使用宿主代理的插件都会被误报。
4. **安装审查把 `secret`、`onnx` 判为「声明了但未使用」**：能力使用检测里缺这两项。
5. **对话框内容溢出**（本轮反馈）：见上表，修在 `DialogContent` / `DialogScrollContent` 组件。
6. **拖放区的「接受的格式」在窄栏里不换行**，溢出到容器外。工作流运行栏变窄后暴露出来；居中的弹性子项保持单行宽度，已限制最大宽度并允许任意位置断行。
7. **PDF 渲染中文乱码（本轮反馈，转换问题，不是预览问题）**：沙盒 Worker 里 pdf.js 注册不了 PDF 内嵌的字体，每个字被画成带编码的缺字方框并栅格化进了输出。所有渲染 PDF 页面的工具都受影响，英文嵌入字体同样如此。修复后与同一字体直接绘制的参照逐像素一致。
8. **扫描件图片渲染为空白、未嵌入中文字体的文字缺失**（排查上一条时发现）：pdf.js 的 CMap、标准字体与 JPEG 2000 / JBIG2 解码器在无网络的沙盒里都取不到。已打包为按需加载的同源资源包。两个问题都先用专门构造的 PDF 复现、确认修复前失败，再加入端到端检查。详见架构文档 15.8。
9. **声谱图慢**（本轮反馈）：先实测——10 分钟音频波形图 0.85 秒、声谱图 310 秒，瓶颈是 FFmpeg `showspectrumpic` 在 wasm 中对整段音频做变换。改为 FFmpeg 只解码、沙盒内用 fft.js 按像素列计算，同一文件降到约 1.3 秒，并补上了频率范围、对数刻度、坐标轴与色标。详见架构文档 15.9。
10. **重复导入占空间、从素材库选择**（本轮反馈）：导入时按内容精确去重，名称不同则共享存储；所有文件输入区新增「从工作区选择」，按工具能处理的类型过滤。为此，文件列表里的「×」改为只取消选择，避免删掉其他工具正在使用的文件。全量回归时发现「同一段音频与自身拼接」被去重合并成了一个输入，改为为第二次选择建立共享存储的别名。详见 15.10。
11. **面板 `row` 里的输入框缩到最小宽度**（做开发者工具时发现）：行内子项按内容宽度排布，时间戳输入框在「现在」按钮旁只剩一小截。改为行内的文本类控件与代码块均分宽度、窄屏换行，含文本域的行顶端对齐；内置的 PDF 签名、视频水印面板随之受益。
12. **侧边栏置顶项拖动排序可能移动错误条目**：按显示列表的下标修改设置，当存在已失效的置顶项（插件已卸载）时两者错位。改为按键移动。
13. 扩展开发中的问题：`definePlugin({...})` 的参数在求值时就用到了文件末尾才声明的常量（暂时性死区），已把这些常量移到文件开头；检测工具使用的图标名 `scan` 不在图标表中，改为 `crop`。

## 四、架构层面

- **Plugin API 只有向后兼容的新增**：工具分类 `dev` 与面板节点 `code`（见架构文档 15.11）。AI 扩展只使用公开能力。
- **沙盒安全架构没有变化**。审查对话框的默认勾选策略保持不变：`secret` 为中风险能力，仍需用户手动开启。本轮修改的是风险报告的说明文字、凭据提示的展示方式与插件记录的持久化，均不涉及隔离边界与授权判定。
- 细节见架构文档第 15 节。

## 五、需要你决定的事项

- **卸载插件时不会清除它保存的凭据与 `kv` 数据**。重新安装同 id 的插件（包括同 id 的另一份代码）即可继续使用之前录入的 Key。是否在卸载时一并清除（或询问），属于凭据生命周期的安全决策，本轮没有改动。扩展 README 已提示用户先删 Key 再卸载。
- 订阅地址目前指向 `@main`。建议发布 0.6.0 时打标签，README 中改为固定标签地址，避免 jsDelivr 缓存导致用户拿到不同步的版本。

# 测试场景覆盖 · 第 2 轮

> 面向：本项目的开发者与评审者。

## 运行

```bash
pnpm test        # 单元测试（vitest，约 0.2 秒）
pnpm test:e2e    # 端到端（Chromium）
```

依次执行：生成素材（PNG、两个 PDF、带音轨的 3 秒测试视频）→ 构建 → 启动带 COOP/COEP 头的 `vite preview` → 顺序跑 4 个套件 → 关闭服务。任一套件失败则整体失败。

测试视频由**系统 ffmpeg** 生成：浏览器内的 FFmpeg 正是被测对象，不能用它自己造素材。未安装系统 ffmpeg 时，媒体相关用例会失败并在生成阶段给出提示。

## 套件与覆盖

### smoke（14）——安全边界

沿用第 1 轮，全部保留：跨源隔离、内置插件注册、`iframe-worker` 隔离层级、OPFS、真实图片压缩、沙盒 iframe 不可达、UI 线程响应、依赖注入、安装审查只列声明能力、越权探针（直连 `fetch` 被 CSP 拦截、IndexedDB 不可达、未授权 `host.net` 与 `host.kv` 被宿主拒绝）、控制台无意外错误。

### tools（22）——工具矩阵

| 分区 | 用例 |
| --- | --- |
| 注册 | 4 个内置插件共 39 个工具全部注册 |
| 数据 | YAML→JSON、CSV 去重、Markdown→HTML、SHA-256 校验（验证 `fs.digest` 替代沙盒内缺失的 `crypto.subtle`） |
| 图片 | 缩放、文字水印、3×3 切图（9 个输出）、图片转 PDF（跨依赖注入）、信息与主色板 |
| PDF | 逐页拆分（3 页→3 文件）、pdf.js 渲染转图片、提取文本、2-up 拼版、水印 |
| FFmpeg | 提取 MP3、**720p 放大转码**、封面帧、媒体探测、**双输入 filter_complex 拼接**、**双遍调色板 GIF** |

后三项加粗的是专门为线程预算加的：它们是最容易撑爆 pthread 线程池的形态（放大 + 解码 + 编码 + 滤镜，或多个解码器同时工作），任何预算退化都会以超时失败暴露出来。

### 单元测试（30）

浏览器套件只能间接覆盖的纯逻辑，单独测：

| 文件 | 用例 | 重点 |
| --- | ---: | --- |

## 未覆盖

- **仍只在 Chromium 上验证**。Firefox 与 WebKit 需重点检查：blob Worker 是否降级、OPFS 写入流、OffscreenCanvas 转交、`BarcodeDetector` 等。
- **ONNX 链路没有端到端用例**：没有接入具体模型，下载确认、SHA-256 校验、缓存命中、会话隔离都未经浏览器验证。
- **`secret` 缺少端到端用例**：域名绑定与加密落盘已有单元测试；还缺浏览器中「录入弹窗 → 带凭据请求 → 沙盒内看不到明文」的完整链路，需要可控的 HTTP 回显端点。
- **订阅链路**依旧只测了本地安装。
- **FFmpeg 取消**：取消会 `terminate()` 实例并在下次重建，这条路径未自动化测试。
- **大文件**：GB 级转码与 OPFS 流式写入仍无实测数据。
- **4 核等小核数机器**：线程预算的下限分支（每路 1–2 线程）没有专门验证。
- **插件内的纯函数没有单元测试**：`parseRanges`、YAML / CSV / XML 解析器目前只经端到端间接覆盖。它们运行在沙盒脚本里、无法直接 import，需要先把可复用逻辑抽成独立模块。
